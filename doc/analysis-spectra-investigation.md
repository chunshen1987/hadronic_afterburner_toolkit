# Analysis and single-particle spectra investigation

Investigated revision `3169027`. The main correctness risks are the multiparticle normalization, the charge-specific acceptance cuts, and the global weak feed-down setting. The largest measured performance opportunity is to remove unused rapidity Q-vector covariance work.

## Correctness findings

| Priority | Finding | Evidence and improvement |
| --- | --- | --- |
| High | Transverse momentum contaminates harmonic-zero tuple counts | The spectra code uses the imaginary part of harmonic zero to store the sum of transverse momenta for mean pT. The correlation routines then treat that slot as part of a complex Q-vector. Four accepted pions at 0.25 GeV should give 12 ordered pairs, 24 triples, and 24 quadruples. The integrated files reported 13 for the pair count, 25 for the triple count, and 42 and 43 for the two four-particle counts. The central Δη pair bin also reported 13. Use the real zeroth moment to calculate the normalization, and check the raw numerators and denominators by enumerating tuples. [Accumulation](../src/single_particleSpectra.cpp#L670) · [Pair kernel](../src/single_particleSpectra.cpp#L999) · [Triplet kernel](../src/single_particleSpectra.cpp#L1291) · [Four-particle kernels](../src/single_particleSpectra.cpp#L1532) |
| High | Charge-specific calculations borrow rapidity from the inclusive list | The positive and negative Q-vector routines take momentum from the charge-filtered list, but apply the rapidity cut using the same index in the inclusive list. The rapidity-binned charge calculation repeats this mismatch. Ordering a forward π⁻ before two midrapidity π⁺ tracks produced zero integrated same-sign pairs, with two expected. Load one track record from the appropriate list and use it for all cuts, weights, and binning. [Positive path](../src/single_particleSpectra.cpp#L615) · [Negative path](../src/single_particleSpectra.cpp#L631) · [Rapidity-binned charge path](../src/single_particleSpectra.cpp#L2183) |
| High | Enabling flow changes weak feed-down in subsequent analyses | Before the second flow pass, `PerformAnalysis` changes the shared parameter dictionary to disable weak feed-down. HBT, balance functions, and yield analysis then construct their readers from that changed dictionary. With 200 one-Λ events and the same seed, a requested weak feed-down run gave one accepted proton in 60% of events with flow off and 0% with flow on. Use a local parameter copy for auxiliary flow passes. Correlation writers also omit the weak-feed-down suffix, allowing the second pass to replace the first pass's files. Make the output key include the decay mode and check it before writing. [Analysis dispatch](../src/Analysis.cpp#L56) · [Integrated correlation writer](../src/single_particleSpectra.cpp#L1145) |
| High | Supported correlation settings can access uninitialized or out-of-range state | Turning off `compute_corr_rap_dep` leaves integrated correlations enabled while skipping initialization of the rapidity grid and correlation reference pT cuts. Setup still uses `N_rap`, and the event loop still reads those pT bounds. Separately, the integrated tuple kernels allow a harmonic index equal to `order_max`, although arrays end at index `order_max - 1`; for example symmetric cumulants request index 8 when `order_max=8`. These are source findings. Initialize integrated settings independently, allocate rapidity storage only for active rapidity observables, and validate the requested harmonics before opening data files. [Integrated-only dispatch](../src/Analysis.cpp#L331) · [Constructor](../src/single_particleSpectra.cpp#L81) · [Rapidity allocations](../src/single_particleSpectra.cpp#L258) · [Reference cuts](../src/single_particleSpectra.cpp#L435) · [Harmonic guard](../src/single_particleSpectra.cpp#L106) |
| Medium | Some uncertainty columns carry the wrong quantity | The differential mean-pT error divides the variance by the square root of track count, leaving units of GeV² in a pT-error column. For four tracks in one bin at 0.24, 0.26, 0.26, and 0.26 GeV, it wrote 0.0000375. The standard error under the same track-independent convention is 0.004330 GeV. The `vn{2}_err` writer propagates the numerator as if reporting a ratio, while the central value is its square root. Define the independent sampling unit and propagate the numerator and pair count jointly. [Mean-pT calculation](../src/single_particleSpectra.cpp#L836) · [Integrated two-particle errors](../src/single_particleSpectra.cpp#L53) |
| Medium | Rapidity outputs mislabel or substitute moments | The harmonic-zero second-moment column in the Δη pair table repeats an integrated moment in every row. An empty Δη bin in the four-pion example had zero pairs but a nonzero second moment of 169. The separate rapidity covariance file is labeled as a density covariance, yet it writes the covariance of unscaled bin counts. Two events with one and three pions in the central bin gave 1.0, the population count covariance. At bin width 0.1, the corresponding density covariance is 100. Write the bin's own moment and make the covariance units explicit before changing values consumed by downstream tools. [Pair table](../src/single_particleSpectra.cpp#L1176) · [Covariance writer](../src/single_particleSpectra.cpp#L2327) |

As a control, a five-track event with distinct azimuths was enumerated directly. After undoing the reported normalization, the nonzero-harmonic integrated triplet, four-particle, and symmetric-cumulant numerators agreed with the explicit sums to within $2.6\times10^{-6}$ in absolute value. This fixture supports correcting the tuple counts before changing the nonzero-harmonic formulas.

## Performance and workflow improvements

**Remove the unused rapidity Q-vector covariance.** Both arrays are allocated and updated for every event with rapidity output. Neither has a reader in this checkout. At 141 rapidity bins and 10 harmonic slots, their double payload is about 3.0 MiB per analyzer, plus row-vector overhead. The update costs two dense $141^2\times10$ accumulations per event per such analyzer. Keep the separate published multiplicity covariance.

| Default flow benchmark | Median wall time | Flow data files |
| --- | ---: | --- |
| Current code | 5.057 s | 134 |
| Scratch build without the unused Q-vector covariance | 2.488 s | 134, byte-identical |

The scratch build took about 51% less wall time on this fixture. This comparison measures one change on one workload.

**Buffer output rows.** Many spectra writers use `std::endl` for every row, including the dense multiplicity covariance. Starting from the scratch build above, replacing those row flushes with newlines reduced the median from 2.494 s to 1.934 s, a further 22% reduction in this separate A/B run. The 134 output files were byte-identical again. [Covariance output loop](../src/single_particleSpectra.cpp#L2345)

**Reuse selections and per-track harmonics.** The driver filters and copies each batch for every spectrum definition, even when several consecutive definitions use the same particle selector with different rapidity or pT cuts. Grouping work by selector would let these definitions share one selected view. Within each selected view, the Q-vector code repeatedly computes pT, azimuth, and harmonic trigonometric values. The differential loop recomputes values already calculated for the integrated loop. Reuse the existing cached track kinematics and compute each harmonic once where selections overlap. A second dead accumulator, the pT-differential scalar-product matrix, is written in memory but never emitted. Confirm whether any consumer needs it before retaining that path. [Batch dispatch](../src/Analysis.cpp#L117) · [Q-vector loop](../src/single_particleSpectra.cpp#L670) · [Differential accumulator](../src/single_particleSpectra.cpp#L993)

**Make the analysis definitions and outputs explicit.** The five flow methods repeat the batch loop and configure each analyzer by mutating the previous parameter set. A list of immutable observable definitions and a shared batch driver would let tests and logs enumerate the exact selections and output keys. Keep the existing filenames for established outputs and check duplicate keys before the run. Distinct rapidity grids need separate files. The count covariance uses all pT, and the Δη correlations use the full rapidity grid. Distinct feed-down modes need separate correlation files. Keep reader sharing between separate analyses conditional on having the same feed-down and input semantics. [Definition setup](../src/Analysis.cpp#L160) · [Rapidity correlation filenames](../src/single_particleSpectra.cpp#L1840) · [Covariance filename](../src/single_particleSpectra.cpp#L2327)

## Reproduction

- Ran all 29 C++ tests from a scratch copy of `unit_tests/` and `EOS/` using the existing OpenMP build. The tests passed.
- Staged the root `parameters.dat` and `EOS/` in each scratch run and ran `hadronic_afterburner_tools.e read_in_mode=9 randomSeed=12345`. The binary fixture used `struct.pack("=i", len(event))` per event and `struct.pack("=i9f", pdg, m, t, x, y, z, E, px, py, pz)` for each track, with zero coordinates and on-shell energy. Pion masses were 0.138 GeV, azimuths and pseudorapidities were zero unless specified, and the charged pT window for the correlation files was 0.2–2 GeV. The charge-index check used pseudorapidity 2.5 for the first track. The nonzero-harmonic control used azimuths `[-2.5, -1.1, 0.2, 0.75, 2.35]` at pT 0.25 GeV and summed over ordered distinct track tuples.
- The weak-feed-down fixture used 200 events with one Λ each at pT 0.6 GeV, zero longitudinal momentum, and mass 1.116 GeV. Compare `analyze_flow=0` and `analyze_flow=1` with `resonance_weak_feed_down_flag=1 analyze_ebe_yield=1 particle_monval=2212 compute_correlation=0`.
- The performance fixture used 400 events of 160 tracks. It cycled through π⁺, π⁻, K⁺, K⁻, p and anti-p with masses 0.138, 0.494 and 0.938 GeV. Python's `random.Random(12345)` generated uniform pT, momentum rapidity, and azimuth on `[0.15,1.5]` GeV, `[-3,3]`, and `[-π,π]`, respectively. On an Intel Core i7-9750H with GNU C++ 15.2, timed `read_in_mode=9 analyze_flow=1 randomSeed=12345` six times per build in alternating order. The medians exclude the first run per build. The only change in the scratch variant removed the two covariance allocations and their accumulation loop. Compared all output files by SHA-256.
- The output-buffering test reused that fixture and compared two scratch libraries with the unused covariance removed. One used the existing row flushes, and one replaced `<< endl` with `<< '\n'` in `single_particleSpectra.cpp`. Ran five trials per library in alternating order and excluded the first per library.

The benchmark uses synthetic collisions. Production input multiplicities, enabled outputs, and storage can change the speedup.

## Fixes and validation

- The spectra accumulator retains $\operatorname{Re}Q_0=N$ and $\operatorname{Im}Q_0=\sum p_T$. The correlation kernels use $Q_0=N+0i$ and subtract self-correlations to count ordered distinct tuples. The integrated and rapidity-difference estimators keep their configured reference pT and rapidity selections. Each charge-specific track supplies its own kinematics. The integrated reference pT cut applies independently of the spectrum histogram range.
- The workflow validates harmonic and grid settings before opening event data, supports integrated-only correlations, and skips flow output when there are no events. Bins with zero eligible tuples retain zero for the normalized correlation and its error. Weak feed-down is scoped to each pass, and each analysis starts from the configured seed. The shared flow driver reuses consecutive particle selections and plans output files before processing. The established basename stays with the last matching definition. Distinct rapidity grids get grid suffixes, and weak-feed-down correlations get `_weakFD`.
- Mean-pT uncertainties use the pooled-track standard error, $\sqrt{(\langle p_T^2\rangle - \langle p_T\rangle^2)/N}$. Two-particle flow uses $v_n\{2\}=\sqrt{R}$ with $R=\sum_e X_e/\sum_e Y_e$, where $X_e$ is the event's pair numerator and $Y_e$ is its ordered pair count. Under independent event sampling, the delta-method error is $\sqrt{\sum_e(X_e-RY_e)^2}/(2\sqrt{R}\sum_e Y_e)$. Rapidity-difference output writes the second moment for its own bin. The multiplicity matrix reports population covariance of reconstructed bin counts. Transverse energy uses $p_T/|\mathbf{p}|$ from the cached momentum, with zero contribution at zero momentum.
- Removed unused rapidity Q-vector covariance and unpublished pT-differential pair accumulators. Spectra reuse the track's cached pT and azimuth and share harmonic evaluations between integrated and differential bins. Text writers buffer rows, and identical rapidity definitions share one output.
